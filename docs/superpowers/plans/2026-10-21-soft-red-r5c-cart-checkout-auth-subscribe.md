# Soft-red R5c: Cart, checkout, auth and brand subscription pages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the cart, checkout, checkout result, sign-in, consent, verify-request and brand-subscription pages the soft-red look (one page-heading scale, bento cards on the new ground, blush cart thumbnail) and make every seller- or user-supplied string on them safe against long unbroken text, **with zero change to cart, checkout, sign-in, consent or subscription behaviour**.

**Architecture:** Class and markup changes only, in the existing page files. Reuse R5a's `PageHeading` and R4's `CoverImage` and tokens (`bg-tint`, `rounded-bento`, `tracking-eyebrow`). No new component, no new query, no new action. The work is **two PRs**: R5c-1 (cart + checkout, the money path) and R5c-2 (auth + brand subscription, the sign-in and subscription path), so each can be reviewed and proved on its own.

**Tech Stack:** Next 15.5, React 19, Tailwind 3.4, Vitest 2.1.9 (jsdom per file), Playwright MCP.

**Spec:** `docs/superpowers/plans/2026-10-16-soft-red-storefront-redesign.md` (R5c line: "type scale and cards only"; R5 rule: "Type scale, spacing and `rounded-bento` only. R5a (`2026-10-20-soft-red-r5a-brand-pages.md`) and R5b (`2026-10-20-soft-red-r5b-product-detail.md`) supply the components, fixture style and evidence format. Facts that shape the plan:

- **`readCheckoutEnabled` writes an `admin_bypass_audit` row on every signed-in load of `/checkout`** (comment in `checkout/page.tsx`). Any browser view of `/checkout` therefore leaves persistent audit rows. The plan counts them and reports them.
- `platform_config.checkout_enabled` is `false` locally and stays so. The checkout form is only visible with the flag on; the browser pass can show it by flipping the flag with owner SQL on the **local dev DB only**, proving the original value is restored. It is never flipped in code and **no payment or subscribe button is ever pressed**.
- Existing tests: `tests/checkout/callouts.test.tsx` (form callouts), `tests/checkout/{initiate,preview,cancel,computeCheckoutTotals}.test.ts`, `tests/auth/verify-request-page.test.tsx` (pins class tokens: its token expectations will change with the look), `tests/auth/{magic-link-actions,auth-config-authorized,auth-error-messages}.test.ts`, `tests/auth/consent/actions.test.ts`, `tests/brand-subscription/*`. **No test renders the cart page, the checkout page, the pollers, the sign-in page, the consent page or the subscribe pages**, so Task A1 and Task B1 pin their behaviour first.
- Suspected weaknesses to prove or disprove on the old code (not assumed): long product, store or variant names overflow cart rows; a 80-character store name overflows the subscribe `h1`; `min-h-screen` under the floating nav makes the auth and subscribe pages taller than the viewport (double scroll); the cart's emoji ignores the dark theme.
