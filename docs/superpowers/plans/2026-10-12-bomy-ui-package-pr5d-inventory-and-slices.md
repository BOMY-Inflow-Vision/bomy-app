## Facts that shape the split

- **How an entry closes.** `scripts/ui-audit/scan.mjs` allows only `open`, `deferred` or `resolved`; `resolved` needs an `evidence` string. There is no "accepted" status. An entry is closed either by **fixing it** (evidence: commit, test, measurement) or, where the finding no longer holds, by **resolving it with written evidence** that Charlie or Bob approved. Nothing is closed silently.
- **Current `@bomy/ui` components:** `Badge`, `Button`, `Card`, `DropdownMenu`, `Input`, `Label`, `Popover`, `Select`, `Textarea`. **Missing:** `Alert`, `FilterTabs`, `Pagination`, `Skeleton`, `EmptyState`, `Sheet`, `FileDropzone`.
- **All 44 entries matched the code when read** (each cited file and pattern was re-read). Line numbers in the ledger are stale in places; slices cite the pattern, not the line.
- **Card is not a drop-in.** `Card` is `rounded-card border bg-card shadow-sm` (card = white in light, `surface-card` in dark; radius 12 px). The hand-made boxes use `bg-background` (sand-50), `rounded-lg` or `rounded-xl`. Moving them to `Card` is a **small visible change** (D3).
- **Behaviour risk is concentrated in:** the mobile menu (`man-b4`, `man-b5`), toasts (`man-b9`), the theme toggle (hydration), the payout buttons (`man-t31`, money paths, className only) and the new drop zone (`man-t12`).
- **The upload zone today** (`image-manager.tsx`): a `<label>` with `onDragEnter/Over/Leave/Drop` wrapping `<input type="file" accept="image/*" className="hidden">`. The input is `display: none`, so **the picker cannot be opened from the keyboard** (a real gap). Validation is "Only image files are allowed" and "Image must be smaller than 2 MB"; upload progress is shown as a percentage and a bar; while `uploading` the zone ignores clicks and drops and the input is `disabled`.
- **Admin sidebar** (`apps/admin/src/components/sidebar.tsx`) computes `active` from the pathname but sets **no `aria-current`** (the seller sidebar does). Found by Bob; fixed in 5d-8.

## Per-slice contract (applies to every slice)

- **Before code:** a short plan naming the exact files, the entries resolved, the expected visible changes, and the proof for each behaviour that could change.
- **Proof, not assumption:** where a slice touches behaviour (nav, toasts, tabs, buttons, the drop zone), write the contract test first against today's markup, then migrate with only representation changes, as in PR 5b. Real-key browser checks for anything keyboard-driven.
- **Contrast:** every new colour pairing gets a token test (both themes), as in 5a-2.
- **Ledger:** each resolved entry gets evidence (commit, test, measurement). Entries that turn out not to apply say why.
- **Gates:** typecheck, lint, web and admin tests, both builds, prettier, `pnpm ui:audit --allow-deferred` exit 0, `ui:audit:test`. Report the two web `DATABASE_URL` files and 13 admin files as **not evaluated**. Stage explicit paths only. Charlie's untracked `apps/web/src/app/products/loading.tsx` stays untracked and unstaged; move it aside for builds.
- **Out of scope in every slice:** `man-5a3`, hold-to-confirm and undo, the magnetic drop zone, the Cloudflare lock. Those stay parked until plain `pnpm ui:audit` exits 0.
